# Instruction to the Code-Server Agent

Read `PLUS_MOOR_PAPER_ALIGNMENT_COMPLETE_REFERENCE.md` and audit the current repository against it.

## Mandatory sequencing

### Phase 1: Inspect and report only

First inspect the current code, configuration, tests, manifests, artifacts, and job state. Do **not** edit code, launch experiments, resume cancelled jobs, overwrite artifacts, or declare the implementation complete during this phase.

Return a detailed status report using the structure below, then stop and wait for review.

### Phase 2: Repair and finish

Only after the Phase 1 report has been reviewed and approval is given, implement the agreed fixes. Work from the acceptance criteria in this document and the controlling scientific reference. Do not launch the full experiment merely because implementation changes compile.

### Phase 3: Verification and readiness decision

After repairs, run unit tests, synthetic scientific tests, and minimal canaries. Return evidence and a readiness recommendation. A full ecological-baseline experiment requires separate approval.

### A. Repository and execution identity

Report:

1. repository path;
2. current branch and commit hash;
3. dirty working-tree files relevant to PLUS/MOOR;
4. exact implementation files for both methods;
5. exact configuration files and method registry entries;
6. tests that exercise each method;
7. active, queued, completed, failed, or cancelled jobs related to the corrected baselines;
8. artifact directories and whether any artifact was generated by the scientifically void provisional implementation.

Do not modify or delete old artifacts. Mark their provenance.

### B. Overall classification

Classify each method as exactly one of:

- **Complete and supported by evidence**
- **Implemented but not sufficiently verified**
- **Partially implemented**
- **Still routed to an old/provisional implementation**
- **Blocked**

Give a short justification. Do not use “faithful” or “complete” based only on method names or comments.

### E. Explicit blocker recheck

Recheck the two blockers that invalidated the provisional implementation.

#### Blocker 1: MOOR observation objective

Show the exact objective code and demonstrate that it compares the observed survey with the conditional mean


#### Blocker 2: regime fit/deployment consistency

Show how discrete regime trajectories are generated under a fixed candidate-specific `Pi`. Demonstrate that fitting, transition-kernel construction, filtering, and planning use the same regime transition semantics. Provide a test that would fail if fitting reverted to a mean-field averaged regime.

## Phase 2 completion rules

After the Phase 1 report is reviewed, implement only approved corrections.

1. Preserve old implementations and artifacts for provenance unless explicitly instructed otherwise.
2. Do not silently route old method IDs to new behavior. Use the registered corrected IDs.
3. Add scientific tests before or with each correction.
4. Keep fit, kernel, filter, and planner parameterization internally consistent.
5. Do not leak true family, `r`, `K`, regime state, action effects, safety threshold, or other private values into hidden mode.
6. Do not add regularization, candidate pruning, early termination, solver fallback, or altered rewards without documenting it.
7. Fail loudly when fitting or PBVI does not converge; do not silently substitute the old regression or QMDP path.
8. Record commit, configuration digest, code digest, data digest, seed, fit diagnostics, solver diagnostics, and wall time in every artifact.

If a computational approximation is necessary, report it before implementing it and explain whether it changes the paper's algorithmic identity or only numerical solution quality.

## Phase 3 readiness evidence

The final completion response must contain:

1. a concise change summary;
2. final PLUS and MOOR component matrices;
3. exact test commands and important output;
4. synthetic-test plots or tables where relevant;
5. limited canary configuration and results;
6. wall-time and memory estimates for the proposed experiment;
7. known limitations and remaining approximations;
8. a statement that the old scientifically void artifacts are excluded;
9. a recommendation on whether the ecological-baseline experiment plan needs adaptation.

Only after this evidence is reviewed should the ecological-baseline experiment be scheduled.
