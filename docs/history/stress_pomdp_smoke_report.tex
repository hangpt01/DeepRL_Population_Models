\section{Scope}

This document reports the short smoke benchmark for the three new POMDP
stress population environments in \path{claude_build}. The goal was not to
produce a tuned final benchmark, but to verify that the new environments,
offline datasets, model-misspecified ecology baselines, WandB logging, Slurm
execution, and stress metrics run end-to-end.

All results are single-seed smoke results. The method evaluation used only
10 deployment episodes per method and should be treated as a framework/demo
check rather than a statistically stable result.

\section{POMDP Environments}

The agent observation is always the public discrete abundance bin
$x_t = \lfloor s_t / 10 \rfloor$, clipped to $0,\ldots,99$. Hidden variables
are sampled or updated inside the simulator and are exposed only through
diagnostic \texttt{info} fields and post-hoc evaluation summaries. They are not
present in the saved offline datasets. The saved dataset arrays contain only
\texttt{states}, \texttt{actions}, \texttt{next\_states}, \texttt{rewards},
\texttt{dones}, and \texttt{metadata\_json}.

For all three stress environments,
\[
    r_{\mathrm{eff}} = r_{\mathrm{base}} + \Delta r(a), \qquad
    K_{\mathrm{eff}} = K_{\mathrm{base}} + \Delta K(a).
\]
The shared reward is
\[
    R_{\mathrm{base}}(x_t,a_t) = x_t/100 - \mathrm{cost}(a_t),
\]
with discount $\gamma=0.95$ during evaluation. In
\texttt{collapse\_sensitive} mode, a one-time penalty of 10 is subtracted when
the transition enters $x_{t+1}\leq 5$ from a nonzero state, and the stress
environment then makes the collapsed state absorbing at bin 0.

\section{Offline Data and Execution}

For each of the six scenario settings, a saved offline dataset with
$N=25{,}000$ transitions was generated using the \texttt{mixed\_danger\_zone}
collection policy. The per-episode mixture was 50\% random, 30\% harvest
pressure, and 20\% rescue. MOPO, RefPlan, and MOOR-Ricker consumed the same
saved dataset path within each scenario. PLUS was evaluated as an ecology
baseline directly from its configured Ricker-assumption model family and does
not consume the saved dataset in this harness.

Slurm jobs were submitted from \path{claude_build/scripts/slurm/stress_pomdp_smoke.sh}.
The dataset array was job 56332820 with tasks 0--5 and the method array was
job 56332834 with tasks 0--23 and concurrency cap 4. WandB was online under
project \texttt{deeprl\_population\_models}, group
\texttt{stress\_pomdp\_smoke\_online}. Each method task requested one GPU,
8 CPUs, and 64 GB RAM; the ecology baselines used CPU internally but inherited
the GPU allocation from the shared array script. Slurm recorded GPU allocation
and node/GPU type, but not peak GPU memory.

\section{Analysis}

The main result is mixed rather than a clean learned-method win. MOPO is the
best method in the theta-logistic stress setting under both reward modes. This
is the setting where the true dynamics are most visibly outside the Ricker
family used by PLUS and MOOR-Ricker, so this is the strongest smoke evidence
that a learned transition model can help when the population model family is
misspecified. In the collapse-sensitive theta setting, MOPO also has a lower
collapse-entry rate (0.10) than the Ricker-assumption baselines (0.30).

In the Allee-Ricker and regime-switch settings, PLUS and MOOR-Ricker tie for
the highest return. The exact ties across several scenarios strongly suggest
that the two ecology baselines are inducing the same, or nearly the same,
deterministic policy under these smoke conditions. This should not be read as
two independent confirmations. It more likely means the current action/reward
structure and low-growth stress tuning make the Ricker-assumption policy good
enough for these short-horizon episodes.

The collapse-sensitive reward mostly lowers returns in settings where collapse
entry occurs. Allee-Ricker drops by about 0.58 for the tied baselines and theta
drops by about 3.0 for the Ricker-assumption baselines because three of ten
episodes enter collapse. Regime-switch has zero collapse-entry events in the
10 evaluation episodes, so the base and collapse-sensitive returns are almost
identical. This makes the regime collapse result a useful plumbing check, but
not a strong stress test of the collapse penalty.

RefPlan is not dominant in this smoke run. It has relatively high reported
entropy/uncertainty, especially in theta-logistic and regime-switch, but this
does not translate to better reward with the small planning budget used here
(64 sequences, horizon 4, 4 latent samples). This may be a tuning issue rather
than a method failure: the run deliberately used a fast smoke configuration.

MOPO is consistently the slowest method because it both trains an ensemble and
uses model rollout planning. RefPlan is much faster here because its tabular
planning budget is smaller. PLUS is usually fastest because it is evaluated
directly without dataset training in this harness. MOOR-Ricker can be fast, but
occasionally spends more wall time in mechanistic fitting/evaluation.

There are three important caveats before drawing scientific conclusions.
First, all numbers use one seed and only 10 evaluation episodes, so a single
collapse episode changes a reported rate by 0.10. Second, the growth priors
were retuned downward after audit because the literal initial stress priors
made the datasets nearly all collapse. Third, peak GPU memory was not captured:
Slurm accounting recorded GPU allocation and node type (A40 or L40S), but no
per-method GPU memory trace.

\section{Recommended Next Steps}

For a real benchmark, rerun this matrix with at least three seeds and 50--200
evaluation episodes per method. Keep the theta-logistic setting because it is
the clearest current misspecification stress case. For Allee-Ricker and
regime-switch, strengthen the stress either by adjusting hidden severity or by
using a start-state/evaluation distribution that more often visits the live
danger zone, while keeping the dataset nondegenerate. Add a lightweight
\texttt{nvidia-smi} sampler or Slurm GPU-memory accounting wrapper if GPU
memory is required in the final table.
