# Corrected Stage B registration templates

These files are templates, not a scientific registration. The execution authorization is
false, the corrected registration is not frozen, and local/M3 code identities are absent.
`freeze_registration_bundle` rejects the templates until an authorized M3 deployment fills
every identity, changes the status to `FROZEN_BEFORE_CORRECTED_RETURNS`, attests that no
corrected return exists, and freezes the complete 24-task manifest.

Successful validation issues a process-local, HMAC-sealed `FrozenRegistration`. Its
constructor and serialization are disabled. Registration-looking bytes or objects created
by any other path cannot open a return sink.

Freeze also recomputes the checked-out Git commit, the three accepted configuration files,
the registered 52/55-file frozen source recipes, the seven-template aggregate and every
ordinary plus normalized-self manifest hash. Task rows must use the distinct I1 tiger/fox
dataset identities and bit-identical O/T configuration, dataset, artifact-plan and
evaluation-identity bindings. Merely well-formed hexadecimal strings cannot freeze.

The mandatory `stageb_interpreter_bindings` section binds both registered roles to an
absolute configured executable, its exact resolved executable, short and full Python
versions, NumPy version, track, methods and logical task indices. Ecological PLUS/MOOR tasks
use `ecological_paper_faithful`; general RefPlan/OGSRL/BA-MCTS/EVD tasks use
`general_registered`. Arm-O gate and inspection-only finalizer roles are explicit in
`command_roles`. Missing, duplicated, extra or runtime-mismatched coverage fails closed.

Earlier sigma=0.2 exploratory results are known. This is a prospective corrected
replication and can never be represented as a blinded preregistration.
