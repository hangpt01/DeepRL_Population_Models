# Reproducing the accepted workflow

## Requirements

- Python 3.10.14.
- The exact dependencies in `requirements.txt`, including the PyTorch CPU index
  directive on its first line.
- The analysis extra, which supplies pandas and matplotlib for the first
  `make verify` stage.
- CPU-only PyTorch 2.13.0+cpu for the paper-faithful fit path.
- The external datasets and fit caches recorded in `data/README.md` and
  `provenance/dataset_hashes.csv`.

Scientific source and configuration come from this repository. Raw datasets,
private trajectories, fit caches, and fit receipts are read from scratch and are
never regenerated by the verification target.

On the accepted cluster, obtain the required interpreter with:

```bash
module load miniforge3/24.3.0-0
PYTHON310=/apps/miniforge3/24.3.0-0/miniforge3/bin/python
"$PYTHON310" --version  # Python 3.10.14
```

Create a clean environment and install both the paper-faithful pins and analysis
dependencies:

```bash
"$PYTHON310" -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install -e '.[analysis]'
```

The requirements file adds
`https://download.pytorch.org/whl/cpu` as an extra index so
`torch==2.13.0+cpu` resolves without an undocumented command-line flag.

## Track selection

Accepted ecological cells:

```bash
export PYTHONPATH="$PWD/src/tracks/ecological"
```

Accepted general-method cells:

```bash
export PYTHONPATH="$PWD/src/tracks/general"
```

Never put both tracks on `PYTHONPATH`.

The tracked compatibility link
`src/tracks/real_ecology_data -> ../../configs/ecology` is load-bearing: it
restores the repository-root table location expected by both frozen packages.
The verification and diagnostic entry points check the link before scientific
work starts.

## Full verification

```bash
make verify \
  SCRATCH_PROJECT=/home/hphung/ce25_scratch2/Claude_DeepRL_Population_Models \
  PYTHON=python
```

The accepted-cell target defaults to A6-MOOR. It uses:

- clean ecological source from `src/tracks/ecological/`;
- clean configuration and manifest rows from `experiments/accepted_p10/`;
- the clean accepted reference table from `results/accepted/`;
- external data, public surrogate, fit receipt, and fit cache from the supplied
  scratch project;
- 20 accepted evaluation episodes of horizon 50;
- a required seven-field maximum absolute difference of `<=1e-9`;
- a required fit-cache reuse gate;
- `recomputed_fits` measured from `policy.fit_diagnostics`, required to equal 0;
- a negative self-test whose deliberately corrupted comparison must exit non-zero.

Outputs go to `.verification/diagnostic_replay/`, which is ignored by Git.

## Individual checks

```bash
make verify-self-tests PYTHON=python
make verify-constants PYTHON=python
make verify-negative-gate PYTHON=python
make verify-cell PYTHON=python SCRATCH_PROJECT=/path/to/Claude_DeepRL_Population_Models
make verify-cell-general PYTHON=python
make verify-standalone-s2 PYTHON=python
```

`verify-cell-general` defaults to B1-EVD and reads scientific source, config, and
the hash-recorded 576-row manifest from this repository. Only its pinned
dataset/surrogate/belief-cache inputs come from `DEEPRL_GENERAL_DATA_ROOT`.

The accepted `xenon-8452Y` Slurm profile is retained at
`configs/cluster/accepted-8452Y.yaml`. A6-MOOR has also passed on the login
6548Y+ host, but other cells should use the accepted profile when strict BLAS
parity is required.

## Results and followups

Small accepted/followup artifacts are committed under `results/` with canonical
scratch paths and hashes in `provenance/copied_artifacts.sha256`.

The final H12 aggregate and receipt were added on 2026-07-29 with:

```bash
python scripts/top_up_followups.py \
  --scratch-project /path/to/Claude_DeepRL_Population_Models
```

The command is idempotent: already-recorded, byte-identical destinations are
verified and skipped.
